Configuration

PDF cover page layout

Controls what appears on the generated PDF's cover page, and in what order. Blank fields are always skipped automatically - a field being mapped here doesn't mean it shows up on every PDF, only on ones where that column actually has a value. Each dropdown offers the columns this tool actually knows about by name (e.g. "Sum: Summa") - see column mapping below to change what any of them point to, including row identity, attachment discovery, and the category folder, which aren't offered as choices here at all. If a choice shows "not found in last fetch," the sheet's real column name may not match what's configured - that's also fixed below.

Sheet column mapping

Maps each thing this tool needs from the sheet to the real column header in your Google Form/Sheet - this is the fix for a dropdown elsewhere showing a column that turns out to have no data, or a "not found" warning on the PDF layout above. The "Sample value" column shows what that column actually holds on the first fetched row, so you can confirm a mapping before saving instead of guessing. Choosing "(Default)" leaves the setting unmapped here entirely, deferring to .env or the compiled-in default instead - the right choice for a column that genuinely doesn't exist in a given sheet (e.g. mileage, for a committee that never reimburses it).

Changes take effect immediately, on the very next action - no restart of `kvittomall webui` or any CLI command is needed, the same as the PDF layout above.

Row identity, attachments, category

⚠ These determine which sheet row a database entry corresponds to, which links get downloaded as attachments, and which final/<category>/ folder a PDF lands in - not just what's displayed. Changing one after entries already exist means those rows won't be found under their new identity on the next fetch - existing downloads/processed files/PDFs aren't deleted, just no longer linked to anything, until reprocessed under the new mapping. Only change these if you're sure.
